# 老年人跌倒检测系统 - 20天路演Demo开发需求

## 项目背景

本项目面向养老看护场景，目标是用多摄像头视觉方案实现”零感知、无佩戴”的老年人跌倒检测。完整商业方案包含硬件部署、隐私架构、分级预警等多层设计，但**当前阶段目标仅为在20天内做出一个能在路演/答辩中演示核心技术可行性的demo**，不追求生产级完整度。

**demo验收标准（明确边界，不要过度工程化）：**

1. 多路（3路）视频输入，YOLOv8 Pose能稳定跑通，输出2D关键点
1. 三视角2D关键点能通过三角测量融合出3D骨骼坐标
1. 3D骨骼特征序列输入BiLSTM+BiGRU分类器，能输出”正常/疑似/摔倒”三级判断
1. “疑似”结果能自动触发本地部署的Qwen3-VL-8B-Q4KM多模态模型进行复核
1. 有一个简单的可视化界面/日志输出，能完整展示上述链路，便于路演演示

**不需要做的事情（避免在这些地方浪费时间）：**

- 不需要真实购买/连接物理摄像头，用数据集视频文件模拟输入即可
- 不需要做完整的隐私加密传输、30秒环形缓冲区落地实现（这些是产品方案里的内容，demo阶段可以只做架构预留或简单mock，不必是完整可用的安全实现）
- 不需要做人工审核通道的实际界面
- 不需要追求生产级的多路并发性能优化
- 不需要做相机的实际标定流程UI，标定参数可以用数据集提供的相机参数或代码里写死的测试参数

## 一、技术架构总览

```
三路视频输入（数据集视频文件模拟三个摄像头）
    ↓
YOLOv8n-pose（每路独立/batch推理）→ 各视角2D关键点 + 置信度
    ↓
多视角三角测量（Triangulation）→ 融合出3D骨骼坐标
    ↓（关键点缺失/低置信度处理）
遮挡补全（骨架运动学约束 + 时序连续性插值）
    ↓
特征工程：从3D关键点序列提取10维特征
（宽高比、躯干倾角、质心速度、关节角度、脊柱矢量 —— 需适配为3D版本的计算方式）
    ↓
BiLSTM + BiGRU + 双向多头自注意力 时序分类器（约150万参数）
    ↓
三级判断：正常 / 疑似 / 摔倒
    ├─ 正常 → 无动作
    ├─ 摔倒（高置信度）→ 直接标记"紧急通道"（demo里做状态展示即可）
    └─ 疑似 → 触发多模态LLM复核
              ↓
        截取关键帧 → 本地部署 Qwen3-VL-8B-Q4KM（GGUF）→ 复核判断
              ├─ LLM判断摔倒 → 紧急通道
              ├─ LLM判断疑似/不确定 → 标记"需人工审核"（demo里只做状态展示）
              └─ LLM判断正常 → 不报警
```

## 二、各模块详细要求

### 模块1：数据集获取与预处理

**用途拆分（重要：两条独立验证线，不要混在一起）**

- **验证线A —— 三维重建正确性验证**：
  用于验证”多视角2D关键点 → 三角测量 → 3D坐标”这套流程本身算得准不准。
  - 优先尝试下载 NTU RGB+D 数据集（该数据集自带官方3D骨骼真值标注，25个关节点，用Kinect v2在同一高度、三个水平角度 -45°/0°/+45° 采集，分辨率1920x1080，30fps）。
  - 如果NTU RGB+D申请审核未通过或耗时过长（该数据集官方需要提交申请表），改用MultiCam Dataset（8视角RGB，可任选3个视角）或 KULeuven Dataset（5视角，场景模拟养老院）作为替代，具体选哪个由你实际下载后评估数据质量、标注完整性、文件可读性决定，优先选择文档清晰、格式易解析的。
  - 验证方法：用自己实现的三角测量流程重建3D坐标，与数据集提供的3D真值对比，计算MPJPE（Mean Per Joint Position Error，平均关节点位置误差）作为核心评估指标。
  - 这一步**只关心重建算法准不准，不需要区分动作是不是摔倒**，可以用数据集里任意动作类别的样本做验证。
- **验证线B —— 摔倒分类判断**：
  用于训练/验证BiLSTM+BiGRU分类器本身的摔倒判断能力。
  - 复用之前已经跑通的 UR Fall Detection Dataset（2D方案，已有精确率77.78%/召回率88.89%/F1 82.35%/AUC-ROC 0.925的基线结果，代码和训练流程应该已有基础，直接复用/迁移）。
  - 如果时间允许，可以尝试将验证线A里获取的多视角数据集（NTU RGB+D等）里的摔倒相关动作类别抽取出来，转换为3D特征后同样喂给分类器训练，作为3D特征方案的初步效果参考（不强制要求完成，视时间进度决定）。

**明确告知使用者（诚实边界）**：这两条验证线目前是分开进行的，还没有做到”用真实三视角实时视频端到端跑通完整摔倒判断”，这是当前demo阶段的已知局限，应在代码注释/README里明确说明，供路演讲解时使用。

### 模块2：YOLOv8 Pose 姿态提取

- 使用 `ultralytics` 库，模型选择 `yolov8n-pose.pt`（最轻量，优先保证跑通，不追求最高精度）。
- 三路视频输入，使用YOLO原生batch推理接口（而不是把多张图物理拼接成一张大图），保持各视角独立分辨率和检测框，避免边界误检问题：
  
  ```python
  from ultralytics import YOLO
  model = YOLO('yolov8n-pose.pt')
  results = model([frame_cam1, frame_cam2, frame_cam3])
  ```
- 输入分辨率统一resize到640x640（等比缩放优先，避免变形），因为YOLO官方预训练权重本身是在640分辨率上训练的，直接输入更高分辨率不会带来精度提升，反而增加不必要的显存和计算开销。
- 每个关键点输出需保留置信度分数，用于后续判断该视角对该点的观测是否可靠。

### 模块3：多视角三维重建

- **相机标定**：如果使用的数据集提供相机内参/外参标定文件，直接使用；如果没有提供，需要用棋盘格标定法或数据集文档说明的方式获取，或者在demo阶段使用简化的手动标定参数（记录清楚这是简化处理）。
- **三角测量（Triangulation）**：将同一关键点在三个视角下的2D坐标，结合标定参数，通过多视角几何三角测量法重建出3D坐标。
- **遮挡与低置信度处理（“反哺”逻辑，重要）**：
  - YOLO本身不具备3D感知能力，也不支持”用外部3D信息修正自身推理”，这一层反哺逻辑需要在YOLO输出之后，作为独立的后处理模块实现，不要尝试修改YOLO内部结构。
  - 具体实现思路：对每个关键点，先用置信度高于阈值的视角做三角测量得到初步3D坐标；对置信度低于阈值（可能被遮挡）的视角，将其余视角重建出的3D坐标反投影（re-projection）回该视角的2D图像平面，用反投影坐标替代/修正原本低质量的2D观测，再重新三角测量一次，提升整体精度。
  - 时序上可加入简单的卡尔曼滤波或滑动平均，利用前后帧的运动连续性平滑单帧噪声和明显异常值。
- **验证**：用验证线A的数据集，对比重建3D坐标与官方3D真值，输出MPJPE指标作为该模块的评估结果，写入demo的评估报告。

### 模块4：特征工程（10维特征，3D版本）

基于3D关键点坐标序列，计算以下5类特征（原方案是2D投影特征，现需要重新设计为3D空间特征，部分特征在3D下会更准确）：

1. **宽高比** → 3D下可替换/补充为人体包围盒的三维尺寸比例，或髋部到头顶的空间距离与肩宽的比例
1. **躯干倾角** → 3D下直接计算脊柱矢量与重力方向（Z轴/地面法向量）的真实空间夹角，比2D投影角度更准确，不受视角影响
1. **质心速度** → 3D空间中质心点（可用髋部中点近似）的真实三维速度矢量，需要用相邻帧的3D坐标做差分计算，注意结合帧率做归一化
1. **关节角度** → 各主要关节（膝、髋、肘、肩）在3D空间中的真实夹角，用向量点积公式计算
1. **脊柱矢量** → 头部/颈部关键点到髋部中点连线在3D空间中的方向向量

最终构成10维特征向量（原方案已有明确设计，需要将2D计算逻辑改写为对应的3D计算逻辑，语义保持一致）。

### 模块5：时序分类器（BiLSTM + BiGRU + 多头自注意力）

- 复用已有架构：BiLSTM + BiGRU + 双向多头自注意力混合架构，约150万参数。
- 训练策略沿用已验证的方案：Focal Loss（α=2.0, γ=2.0）配合SMOTE过采样解决类别不平衡问题。
- 输出调整为**三分类**（正常 / 疑似 / 摔倒），而非原来的二分类（摔倒/非摔倒）。三级划分建议：
  - 模型输出摔倒类别概率高于较高阈值（如0.85）→ 判定”摔倒”
  - 模型输出摔倒类别概率处于中间区间（如0.4-0.85）→ 判定”疑似”，触发LLM复核
  - 模型输出摔倒类别概率低于较低阈值（如0.4）→ 判定”正常”
  - 具体阈值需要根据实际测试集上的概率分布调整，代码里应做成可配置参数，不要写死，并在评估报告里说明选择依据。
- 使用验证线B的数据训练，输出精确率、召回率、F1、AUC-ROC等指标，与原2D方案基线对比。

### 模块6：多模态LLM复核（本地部署）

- 模型：Qwen3-VL-8B，使用Unsloth已经量化好的GGUF Q4_K_M版本（从HuggingFace的unsloth相关仓库下载现成量化权重，不需要自己做量化或微调）。
- 推理框架：由你根据实际本机环境（GPU型号、显存、系统环境）自行判断选型，常见选项包括 llama.cpp（含视觉多模态支持，注意需要配套下载mmproj视觉投影层文件）、Ollama（底层同样基于llama.cpp，封装更简单）等，选型时优先考虑部署简便、社区支持成熟、能正确处理视觉输入的方案。
- 触发逻辑：仅当分类器判断为”疑似”时才调用，避免不必要的推理开销。
- 输入：从触发时间点附近截取1-3帧关键画面（不需要发送完整30秒视频，控制推理成本和延迟）。
- Prompt设计要求：明确要求模型判断画面中人物是否处于摔倒/异常倒地状态，要求输出结构化结果（如JSON格式，包含判断结论和简要理由），便于代码解析后续流程分支。
- 输出结果需要能驱动后续分支（摔倒/疑似/正常三种复核结果对应不同的demo展示状态）。

### 模块7：Demo可视化/展示层

- 目标：让路演观众能直观看懂整个系统的实时运作流程，不需要做复杂前端，简洁清晰即可。
- 建议实现方式（任选其一，根据开发效率决定）：
  - 简单的网页界面（实时展示三路视频画面 + 骨架叠加渲染 + 当前判断状态 + 触发LLM时的复核过程和结果）
  - 或命令行/终端输出 + matplotlib/opencv实时画面窗口，展示同样的信息流
- 展示内容应包含以下状态流转，让观众能看到完整链路：
1. 三路视频画面（可叠加渲染出检测到的骨架关键点）
1. 当前3D重建状态
1. 分类器实时输出的正常/疑似/摔倒判断及置信度
1. 触发LLM复核时的提示（例如”检测到疑似情况，正在调用本地视觉模型复核…”）
1. 复核结果与最终判定状态
